# M-ONE Rubric Traceability and Eligibility

**Source basis:** `Guidebook_MONE_Coding_Competition_REVISI (1).pptx` and `TM_M-ONE (1).pptx` supplied in this conversation. Relevant guidebook pages: 4 (schedule), 5–6 (eligibility gates), 7–8 (weights/indicators), 9–11 (judging/start line/originality/sanctions), and 12 (submission). This is a transcription of the supplied guidebook, not an organizer-issued amendment.

## 1. Hard eligibility gates

The guidebook pages 5–6 list six gates; a work that misses a gate or cannot prove it will not be assessed further:

1. AI Agent reference docs for all development tasks.
2. Public GitHub repository.
3. Curated prompt journal, maximum five prompts, plus raw prompt log from beginning to end. The raw log is for verification and is not itself scored.
4. Relevant to “Innovating Education Through Technology” and subtheme “Web Education for Kids” (elementary school).
5. Free choice of technology stack.
6. Deployed website accessible to organizers/judges.

A beautiful product does not compensate for a missed eligibility gate.

## 2. Official scoring weights

| Criterion | Weight | Guidebook indicators | CogniFlip evidence |
|---|---:|---|---|
| Vibe Coding Process | 25% | Clear/structured AI Agent docs; orderly, specific, iterative prompts; debugging prompt demonstrates problem understanding | `CLAUDE.md`, project docs, authentic prompts/logs, actual debugging evidence, test results, traceable changes/commits |
| Functionality & Theme Relevance | 25% | Features work, align with theme/subtheme, address an education challenge, easy to use | End-to-end Teach the Robot; child-friendly coding lessons; evidence-based scoring/revision; deployed AI integration; honest failure/retry handling |
| UI/UX & Responsiveness | 20% | Mobile/desktop layouts; non-generic colors/typography; smooth in/out animation; relevant hover/asset use | Design system, age-appropriate language, responsive checks, accessible interactions, relevant mascot/illustrations, reduced motion |
| Technical Quality | 15% | Clean code/folder structure; performance/lazy loading/compressed assets/basic SEO; good commit messages | Module boundaries, type/schema validation, lint/type/build/test results, lazy editor, optimized assets, SEO metadata, real commit history |
| Innovation & Creativity | 15% | Innovative features beyond baseline; original idea with real value; relevant additional features/pages | Integrated Explain → Code → Predict → Diagnose → Improve loop, evidence-grounded code review, child-friendly learning, collaboration if complete and safe |

## 3. Tie-break rule

If final scores tie, the guidebook prioritizes:
1. Vibe Coding Process.
2. Functionality & Theme Relevance.
3. UI/UX & Responsiveness.

Authentic process evidence and end-to-end behavior matter at least as much as a polished landing page.

## 4. Originality and start time

The guidebook pages 9–11 say repository, code, design and AI Agent docs must be created after the start line: **5 October 2026, 09:30 WIB**. Ideas/concepts may be prepared earlier without finished code, designs, or documents. Prohibited practices include using an older repository/fork/template, copying previous code/components/pages (including one's own), reusing prewritten AI Agent docs/prompts, rewriting commit history with force-push, or falsifying timestamps.

The guidebook states a 35% score reduction for proven prior-project usage and disqualification if originality cannot be proven. It also states disqualification for plagiarism, private GitHub repository, manipulated prompt documentation, and late submission without prior organizer-approved confirmation. Organizer-approved late submission is described as a 10% score reduction.

An MIT license or personal ownership does not override the contest rules. Older projects can be used as conceptual inspiration where permitted, but the actual contest implementation must follow the guidebook and be developed from scratch. Preserve authentic history.

## 5. Schedule and submission

The supplied guidebook page 4 states:
- 5 Oct 2026, 09:00 WIB: preliminary round opens/preparation.
- 5 Oct 2026, 09:30 WIB: official start line.
- 15 Oct 2026, 15:30 WIB: submission deadline.
- 15 Oct 2026, 21:00 WIB: preliminary round closes, explicitly not the submission deadline.
- 16–24 Oct 2026: judging.
- 25 Oct 2026, 15:00 WIB: announcement.

Verify authenticated organizer updates and record their source/time if anything changes.

## 6. Evidence index

For each criterion, keep an evidence index containing artifact path, actual date/time, what it demonstrates, and how to reproduce it. Do not invent judge scores. Internal self-audit is not a prediction of actual ranking.
